# Document swapping the session store for a cache-backed one

## What changed

- `README.md`: new **Sessions** section. It records the default (the router's
  native `$_SESSION` store, bound by the generated
  `lib/App/Provider/Session.php`) and shows how to swap in the router's
  cache-backed `Strukt\Http\Session\Cache` store so sessions can be shared
  across processes or servers.

No application code changed: the provider keeps binding
`Strukt\Http\Session\Native`. This is a documentation-only change.

## Why

`strukt/router` 1.2.0 added a session store backed by any `strukt/cache`
driver, so an app that runs behind a load balancer no longer has to write its
own store. The skeleton keeps the native store as the default because the cache
store needs `strukt/cache` (and, for the memcached driver, a running server),
which a fresh single-server install should not require. The README now points
users at the swap when they need it.

## Documentation

- `README.md`: new **Sessions** section with both bindings and a link to the
  router's `docs/http-layer.md` and `docs/authentication.md`.

## Tests

- None (documentation-only). The `Cache` store itself is covered by
  `strukt/router`'s `CacheSessionTest`.

## Public API impact

- None. The skeleton still requires only `strukt/framework`; the cache store is
  opt-in and already available because the framework pulls in `strukt/cache`.
