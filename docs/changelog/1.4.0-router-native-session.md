# Use the router's native session store

## What changed

- Deleted the application-level `Web\NativeSession` class.
- `App\Provider\Session` now binds `Strukt\Http\Session\Native` (from
  `strukt/router`) as the router's session factory, so the `$_SESSION`-backed
  store lives in the package instead of the app.

## Why

`Strukt\Session` is an in-memory store, so the app had to override it to persist
across requests. `strukt/router` now ships `Strukt\Http\Session\Native`, which
does exactly that — including persistent flashes — so the app no longer carries
it. This mirrors strukt1, where the native store lived in `strukt-router`.

## Documentation

- None in this package; the store is documented in `strukt/router`
  (`docs/http-layer.md`, `docs/authentication.md`).

## Tests

- None in this package (the skeleton has no test suite). Covered by
  `strukt/router`'s `NativeSessionTest`; verified end-to-end here by logging in,
  restarting the request, and reading the profile from the persisted session.

## Public API impact

- Requires `strukt/router` with `Strukt\Http\Session\Native` (>= 1.1.0).
