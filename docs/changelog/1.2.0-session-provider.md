# 1.2.0 — Dedicated session provider and the router session middleware

## What changed

Session wiring was lifted out of the auth provider into its own provider, and
the router's own session middleware is now in the pipeline:

- `App\Provider\Session` — a new auto-discovered provider. `register()` binds
  the router's session factory to `Web\NativeSession` and queues the router's
  session middleware with `router()->middleware('sess')`. The `sess` alias
  resolves to `Strukt\Router\Middleware\Session` through the router's built-in
  named-middleware registry, so the middleware is reused rather than
  re-implemented.
- `App\Provider\Auth` — no longer sets the session factory; it now only binds
  `router()->verify(...)` (resume the user) and `router()->permissions(...)`
  (RBAC). Session ownership moved to `App\Provider\Session`.
- `Web\NativeSession` — the `$_SESSION`-backed store moved from
  `Web\AuthModule\Http\NativeSession` to the application root (`Web\`), so the
  bootstrap provider no longer depends on a specific module. `Http/` under
  `AuthModule` was removed.

Behaviour is unchanged: the store still persists a login, and the router
middleware now also hands that same store to the request
(`$request->session()`).

## Why

A session is application infrastructure, not an authentication detail: the auth
provider should only decide *who* the user is, while the store and the
middleware are transport concerns. Splitting them keeps each provider focused
and makes the store reachable from the request via the framework's existing
`Strukt\Router\Middleware\Session`, instead of a one-off attachment. The store
stays app-side because the framework ships no `$_SESSION`-backed implementation
(`Strukt\Session` is in-memory only).

## Documentation

The booted application code lives under `app/` and `lib/`, both git-ignored, so
this is recorded here. This supersedes the session wiring described in
`1.2.0-auth-routes.md`.

## Tests

No automated tests in the skeleton (it is a Composer project). Verified by hand
against a fresh server (database deleted to reseed), plus a scratch bootstrap
that dispatched a request and inspected the pipeline:

- `router()->middlewareList()` is `["sess"]` and the dispatched request's
  `session()` is a `Web\NativeSession`.
- guest `GET /user/list` → `401`; `user@strukt.test` login → `200`, profile
  `200`, `/user/list` `403`; `POST /logout` → `200`, profile afterwards `401`;
  `admin@strukt.test` `/user/list` → `200`; `GET /rbac` → `200`.
- `php -l` is clean and no references to `Web\AuthModule\Http\NativeSession`
  remain.

## Public API impact

Skeleton only, within git-ignored generated directories. No framework or package
code changed; the router session middleware is consumed as shipped.
