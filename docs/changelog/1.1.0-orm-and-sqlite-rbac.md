# 1.1.0 — Require `strukt/orm` and build the SQLite RBAC app

## What changed

The skeleton now pulls in the ORM package set so a booted application can
persist to a database out of the box:

- `composer.json` requires `strukt/orm` (`dev-main`) and declares `path`
  repositories for `../orm` and `../ar`, alongside the existing framework
  siblings.
- `.gitignore` ignores `/database/`, where the SQLite file lives.

Booting the skeleton (`composer install`, `app:make Web`, `app:reload`) and
building a role-based access control layer in the generated `Web\AuthModule`
was used to prove the wiring. That application code is generated and
git-ignored, so it is not part of the tracked package; it is described here for
the record:

- `Web\AuthModule\Model\{User,Role,Permission,RoleUser,PermissionRole}` —
  `strukt/ar` active-record models declaring the `$schema` for the five RBAC
  tables (`users`, `roles`, `permissions`, `role_user`, `permission_role`).
- `Web\AuthModule\Rbac` — a service over `strukt/orm`; `install()` compiles the
  tables with `Strukt\Ar\Schema` and seeds defaults once, reads go through
  repositories, and writes (`grant`/`revoke`/`allow`/`deny`) go through the
  unit of work.
- `lib/App\Provider\Database` — auto-discovered provider that opens the default
  SQLite connection at `<root>/database/app.db`, installs the schema, seeds the
  defaults, and registers the RBAC permission resolver on the router.
- `Web\AuthModule\Router\Rbac` — `/rbac…` endpoints to inspect and mutate roles,
  permissions, and user grants, plus a `@Permission(role.manage)`-guarded route.

## Why

The next toolkit iteration needs a database layer; `strukt/orm` (over
`strukt/ar`) is that layer, and an RBAC is the natural first consumer. Wiring it
into the booted skeleton validates the provider-discovery, schema, unit-of-work,
and router-authz integration end to end before anything is promoted into the
framework templates.

## Documentation

`README.md` continues to describe the framework-only skeleton; the RBAC is a
booted-instance demonstration, so no skeleton doc page was added. This changelog
records the tracked change (`composer.json`, `.gitignore`).

## Tests

No automated tests in the skeleton (it is a Composer project). Verified by hand:
`composer install` links 15 packages, `route:ls` registers the `/rbac` routes,
serving the app returns the seeded roles/permissions/users, `grant`/`revoke`/
`allow`/`deny`/create endpoints persist through the ORM, and the
`@Permission(role.manage)` route answers `401` for a guest.

## Public API impact

Skeleton only: the project now depends on `strukt/orm` and `strukt/ar`. No
changes to the framework or other packages.
